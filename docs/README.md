## 作成優先順位

実装開始前に揃えるべき順序：

1. `glossary.md` — 言葉を統一しないと他のドキュメントも曖昧になる
2. `product-vision.md` — 全判断の拠り所になる
3. `adr/` — 実装開始前に技術決定を記録する（必須）
4. `collaboration.md` — ステージング環境が動き始める前に顧客へ共有する
5. `definition-of-done.md` — 最初のスプリント開始前に合意する
6. `data-model.md` — スキーマ設計前に概念を整理する

## アジャイル開発におけるドキュメントの原則

- **動くソフトウェアが最優先**。ドキュメントは会話の補助であり、契約書ではない。
- 顧客との認識合わせは**ステージング環境でのデモ**が最も確実。ドキュメントはその前後の補助として使う。
- ドキュメントはスプリントごとに**必要な分だけ**作る。全部揃ってから実装しない。
- ADR は**後から覆せない技術決定**のみ記録する。変わりうる実装の詳細は書かない。
