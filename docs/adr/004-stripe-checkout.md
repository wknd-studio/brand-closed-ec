# ADR-004: 注文決済に Stripe Checkout（固定価格）と Stripe Invoice（要相談）を採用する

## ステータス

Accepted（旧タイトル「Stripe Invoice を採用する」から変更）

## コンテキスト

会員が商品を注文する際の代金回収方法を決定する必要があった。このサービスは**無在庫転売型**であり、注文を受けた後に運営者が仕入れ先へ発注する。カートに入れる商品には2種類ある。

1. **固定価格商品**: ランク別に価格が決まっており、注文時に合計金額が確定する
2. **要相談商品**: 仕入れ先との交渉次第で価格が決まり、注文時は金額未確定

要相談商品を含む注文は注文と同時に決済を完了できないため、一律に即時決済モデルは採用できない。一方、全商品が固定価格の注文では運営者の手作業をゼロにして会員・運営者の双方の体験を向上させたい。

## 決定

カートの内容に応じて決済フローを自動分岐する。

| 条件                    | フロー              | 仕組み                                                                                                    |
| ----------------------- | ------------------- | --------------------------------------------------------------------------------------------------------- |
| 全商品が固定価格        | **Checkout フロー** | Stripe Hosted Checkout で即時決済。`checkout.session.completed` Webhook でステータス更新                  |
| 要相談商品を1つでも含む | **Invoice フロー**  | 運営者が Stripe Invoice を手動発行。会員はメールのリンクから決済。`invoice.paid` Webhook でステータス更新 |

どちらの場合も、カード情報の入力は stripe.com にホストされたページで行うため **SAQ A 準拠**を維持できる。

### 決済フロー（Checkout）

```
全商品が固定価格 → 月次上限チェック（全額）→ Checkout Session 作成
→ 会員が stripe.com でカード入力・即時決済
→ checkout.session.completed Webhook → ステータス「入金確認済み」へ自動更新
```

### 決済フロー（Invoice）

```
要相談商品を含む → 月次上限チェック（固定価格分のみ）→ 注文「注文確認中」で記録
→ 運営者が仕入れ先と価格交渉
→ 運営者が管理画面で請求金額を入力 → 月次上限チェック（全額）
→ 運営者が Stripe Invoice 発行・送付
→ 会員がメールのリンクから stripe.com で決済
→ invoice.paid Webhook → ステータス「入金確認済み」へ自動更新
```

## 代替案

| 案                               | 却下理由                                                                           |
| -------------------------------- | ---------------------------------------------------------------------------------- |
| Invoice フローのみ（全注文一律） | 固定価格のみの注文でも運営者の請求書発行作業が発生し、運用コストが不必要に高くなる |
| Stripe Elements（カスタム UI）   | SAQ A-EP 準拠が必要になりセキュリティ要件が増える                                  |
| 他の決済プロバイダ（PayPay 等）  | Stripe Subscription（会員ランク課金）との統合が前提のため、一本化を優先            |
| 自前決済実装                     | PCI DSS 完全準拠が必要となり、現実的でない                                         |

## 結果

### メリット

- 固定価格のみの注文は運営者の手作業ゼロで決済完了できる
- 要相談商品を含む注文でも、請求書発行のタイミングで金額を確定できる
- カード情報が自社サーバーを経由しないため、**PCI DSS SAQ A** に準拠できる
- 両フロー共通で Stripe が支払いページを担当するため、実装工数を削減できる
- `checkout.session.completed` / `invoice.paid` Webhook で入金確認を自動化できる

### 制約・注意点

- `Order.payment_flow`（`checkout` | `invoice`）で注文確定時にフローを記録し、以降変更不可
- Webhook の受信エンドポイントは署名検証を必ず実装する
- Checkout Session・Invoice の作成 API 呼び出しは Server Action で行い、Stripe 秘密鍵をクライアントに渡さない
- 入金後のキャンセルは Stripe Refund が必要。返金ポリシーは原則返金なし、例外は運営者判断（システム外処理）
- 会員ランクの月額費用は Stripe Subscription で管理する（ADR-007 参照）。Checkout / Invoice は注文代金のみに使用する
