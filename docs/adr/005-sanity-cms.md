# ADR-005: 商品・コンテンツ管理に Sanity CMS を採用する

## ステータス

Accepted

## コンテキスト

商品情報（画像・説明文・カテゴリ）やお知らせといったコンテンツを管理する仕組みが必要だった。運営者がエンジニアなしでコンテンツを更新できることが求められており、また商品画像の CDN 配信も必要だった。一方、商品の価格・在庫・ランク制限といった EC の基幹データは Supabase で管理する必要がある。

## 決定

コンテンツ管理に **Sanity CMS v3** を採用する。商品の「見た目に関する情報」（画像・説明・カテゴリ）は Sanity で管理し、「取引に関する情報」（価格・在庫・ランク制限）は Supabase で管理する。

## 代替案

| 案                    | 却下理由                                                                      |
| --------------------- | ----------------------------------------------------------------------------- |
| Supabase のみで全管理 | 画像の CDN 配信・リッチテキスト編集・運営者向けの使いやすい管理 UI が不足する |
| Contentful            | Sanity と比べてカスタマイズ性が低く、コストも高い                             |
| Shopify（ヘッドレス） | EC 機能との二重管理になり、Stripe との統合設計が複雑になる                    |

## 結果

### メリット

- **Sanity Studio** という管理 UI が標準で提供され、運営者がエンジニアなしで商品情報を更新できる
- Sanity CDN で商品画像を最適化して配信できる
- `next-sanity` を通じて GROQ クエリで型安全にコンテンツを取得できる

### 制約・注意点

- **商品データが Sanity（コンテンツ）と Supabase（EC データ）に分散する**。`sanity_id` をキーに両者を紐付ける
- 商品の登録は Sanity Studio と Supabase 管理画面の両方で作業が必要になる
- Sanity Studio は `sanity deploy` コマンドで別途デプロイが必要
