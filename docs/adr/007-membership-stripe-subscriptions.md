# ADR-007: 会員ランク管理に Stripe サブスクリプションを採用する

## ステータス

Accepted

## コンテキスト

会員はランクごとに月額費用を支払う。会員自身がいつでもランクをアップグレード・ダウングレードでき（SaaS のようなセルフサービス）、変更に伴う請求額の調整が自動で行われる必要がある。月額課金の管理・プラン変更・請求書発行を自前で実装することは現実的でない。

## 決定

会員のランク別月額課金の管理に **Stripe サブスクリプション**を採用する。各ランク（Entry・Standard・Pro）を Stripe の Product / Price として登録し、会員のランク変更時に Stripe のサブスクリプションを更新する。

> Free ランクは月額 ¥0 のため Stripe サブスクリプション不要。Enterprise は要相談のため個別対応。

## 代替案

| 案                                 | 却下理由                                                                                      |
| ---------------------------------- | --------------------------------------------------------------------------------------------- |
| 手動請求（請求書を都度発行）       | ランク変更のたびに手作業が発生し、運営コストが高い                                            |
| 他のサブスクリプション管理サービス | Stripe Checkout（商品購入）と同じプロバイダに統一することで、Webhook 管理・会計の一元化が可能 |
| 自前でサブスクリプション実装       | 請求管理・プロレーション計算・失敗時のリトライ等の実装コストが大きい                          |

## 結果

### メリット

- Stripe がプロレーション（月の途中でプランを変更した際の日割り計算）を自動処理する
- ランク変更・課金失敗・解約を Webhook で受信してデータベースに反映できる
- Stripe の管理画面で請求履歴・会員ごとの支払い状況を確認できる
- 商品購入（Checkout）と会員課金（Subscription）を同一の Stripe アカウントで管理できる

### 制約・注意点

- **ランクの状態が Stripe と Supabase の2箇所に存在する**。Webhook 受信後に `users.rank` を更新し、常に同期を保つ必要がある
- Webhook の処理は冪等性を担保する（同じイベントを2回処理しても結果が変わらないようにする）
- Enterprise の月額は要相談のため、Stripe の Custom Pricing または手動請求で対応する
- ランク変更の即時反映 vs 翌月反映は今後決定する（TBD）
