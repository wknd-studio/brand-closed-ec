## サービス概要

招待制クローズド EC。招待コードを持つ方のみ登録でき、特定ブランドの商品を卸売価格で仕入れられる。
会員ランクごとに月額費用・月間仕入れ上限・商品単価・利用できる機能が異なる。

## 利用者

このサービスに関わる人物の役割一覧。プランごとの機能差異は「会員プラン」セクションで定義する。

| 役割               | 説明                                                                                                                                         |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------- |
| **会員**           | 招待コードで登録した利用者。カタログ閲覧・手配リクエスト・注文・マイページ管理が行える。プランに応じて利用できる機能・月間仕入れ上限が異なる |
| **管理者**         | 全機能にアクセスできる運営者。担当者アカウントの管理も担う                                                                                   |
| **請求・顧客担当** | 請求書の発行・会員からの問い合わせ対応を担う運営者                                                                                           |
| **調達担当**       | 仕入れ先への発注・注文ステータスの更新を担う運営者                                                                                           |

## 共通ルール（全会員）

- **招待コードは全ランクで必須**。招待なしでは登録できない。
- 全ランクでカタログ閲覧・手配リクエスト・購入が利用できる。専用契約・SLA 対応は ENTERPRISE のみ。
- プラン間の主な違いは月額費用・月間仕入れ上限・商品掛け率。
- 月間仕入れ上限はサブスク登録日を起点として1ヶ月ごとにリセット（例: 1/15登録 → 毎月15日リセット）。
- 商品にはランク制限を設定できる。最低閲覧ランクを下回る会員はその商品を閲覧・購入できない。
- **会員自身がいつでもランク変更可能**（セルフサービス）。アップグレードは即時反映、ダウングレードは期末適用。

## 招待システム

### 招待の仕組み

- 登録には招待が必須。招待なしでは登録できない。
- 招待は「招待する側が相手のメールアドレスを入力する」形式。入力されたアドレスに招待メールが送られる。
- **管理者**は常に招待を発行できる。
- **会員**は招待権限が付与されている場合に限り発行できる。招待権限の付与・剥奪は管理者が行う。
- 会員ごとに招待上限数・使用済み招待数を管理する。管理者は上限数を自由に設定できる。
- 招待には有効期限を設定できる。

### 招待の記録

誰が誰を招待したかを DB に記録する（`invited_by_user_id`）。将来のアフィリエイト特典の計算に使用する。

## ランク変更ルール

### 初期費用の差分請求

- アップグレード時は `新プランの初期費用 − 支払い済み最高ランクの初期費用` の差分を請求する
- ダウングレード時は初期費用の返金なし
- 支払い済み最高ランク（`initial_fee_paid_rank`）は DB に保持し、退会後も維持する

**例：**

```
STARTER 登録（初期 ¥5,000 支払い）→ initial_fee_paid_rank = STARTER
  ↓ PRO にアップグレード
  差分 ¥45,000（¥50,000 − ¥5,000）請求 → initial_fee_paid_rank = PRO
  ↓ BASIC にダウングレード
  初期費用変動なし → initial_fee_paid_rank = PRO のまま
  ↓ 退会・再入会（STANDARD で入会）
  STANDARD ≤ PRO → 初期費用免除
  ↓ PREMIUM にアップグレード
  差分 ¥280,000（¥330,000 − ¥50,000）請求 → initial_fee_paid_rank = PREMIUM
```

### 変更後の月間仕入れ上限

**アップグレード時**

アップグレード日を新しい起点として請求期間がリセットされる。使用済み額は ¥0 から再スタート。新プランの上限をフルで使える。

**ダウングレード時**

期末適用（更新日まで現プランのまま継続）。更新日から新プランが適用される。更新日前であればダウングレードを取り消せる。

## 注文キャンセル

### 会員によるキャンセル

支払い前のステータスであれば会員自身がキャンセルできる。支払い後はキャンセル不可（オペレーターへ問い合わせ）。

| ステータス        | フロー   | 会員キャンセル                |
| ----------------- | -------- | ----------------------------- |
| `pending_payment` | Checkout | ✅ 可                         |
| `confirming`      | Invoice  | ✅ 可（確認ステップあり）     |
| `invoice_sent`    | Invoice  | ✅ 可（確認ステップあり）     |
| `paid` 以降       | 両方     | ❌ 不可（オペレーターへ連絡） |

`confirming` / `invoice_sent` でキャンセルする場合、確定前に「担当者がすでに作業を開始しています。キャンセルしてよいですか？」という確認ステップを表示する。

### オペレーターによるキャンセル

| ステータス          | 実行できる役割               | Stripe 追加作業            |
| ------------------- | ---------------------------- | -------------------------- |
| `pending_payment`   | 管理者・請求顧客担当         | なし（Session は自動失効） |
| `confirming`        | 管理者・請求顧客担当         | なし（Invoice 未発行）     |
| `invoice_sent`      | 管理者・請求顧客担当         | Invoice を void する       |
| `paid` 〜 `ordered` | 管理者のみ                   | Stripe で返金処理          |
| `preparing` 以降    | 原則不可（管理者が個別判断） | 返金 + 返品対応が必要      |

## アカウント停止

### 停止できる操作

管理者は任意の判断で以下を実行できる。

| 操作         | 内容                                     | 可逆性 |
| ------------ | ---------------------------------------- | ------ |
| **停止**     | アクセスをブロックし、課金を一時停止する | 可逆   |
| **強制退会** | 管理者権限で会員を退会させる             | 不可逆 |

### 停止中の扱い

- ログインおよびサービスの利用をブロックする
- Stripe のサブスクリプションを一時停止する（停止期間中の請求は発生しない）
- 進行中の注文は継続して処理する。新規注文はブロックする

### 停止の解除

- 管理者が停止を解除するとアクセスが即時復活する
- Stripe の課金は次の請求期間から再開する（停止期間分は請求しない）
- 月間仕入れ上限は停止前の使用済み額を引き継ぐ

### 管理者による強制退会

- `paid` 以降の注文がある場合でも管理者は実行できる（会員自身の退会チェックを迂回）
- 管理画面に「入金済みで処理中の注文が N 件あります」という確認ステップを表示する
- `paid` 以降の注文はそのまま完走させる。運営側が手動で完了・キャンセルまで処理する
- アカウント処理（ログインブロック・Stripe 解約・論理削除）は即時実行する

## 退会・再入会

### 退会

- 入会日から **6ヶ月間は退会できない**（最低利用期間）。
- `paid` 以降（`paid` / `sourcing` / `ordered` / `preparing` / `shipping`）の注文が1件でもある場合、退会をブロックする。
- `paid` より前のステータス（`pending_payment` / `confirming` / `invoice_sent` / `limit_exceeded`）は退会をブロックしない。
- 退会後もデータは保持する（論理削除）。
- 退会と同時に Stripe サブスクリプションを解約する。

### 再入会

- 注文履歴・住所などのデータは引き継ぐ（論理削除のため保持済み）
- プランは再入会時に改めて選択する
- 初期費用は `initial_fee_paid_rank`（支払い済み最高ランク）を基準に判定する
  - 選択プラン ≤ `initial_fee_paid_rank` → 初期費用免除
  - 選択プラン ＞ `initial_fee_paid_rank` → 差分（選択プランの初期費用 − 支払い済み最高ランクの初期費用）を請求

## 禁止事項

### アカウント・招待関連

- アカウントの第三者への譲渡・共有
- 招待コードの転売・譲渡
- 虚偽情報での登録

### 利用目的関連

- 仕入れた商品の転売
- 競合他社によるリサーチ目的での登録

### システム関連

- 不正アクセス・クローリング
