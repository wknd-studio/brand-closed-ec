# 完了の定義（Definition of Done）

「完了」とは何かを定義する。ユーザーストーリーの実装・バグ修正が「完了」と見なされるための基準。
顧客・開発者が同じ基準を共有することで、手戻りを防ぐ。

---

## フィーチャー（ユーザーストーリー）の完了基準

以下をすべて満たしたとき、ユーザーストーリーは「完了」とする。

### 1. 受け入れ条件を満たしている

- `user-stories.md` に記載された受け入れ条件（【ユーザーが確認できること】【システムが保証すること】）をすべて満たしている
- ステージング環境で実際に操作して確認済み

### 2. コード品質

- `pnpm typecheck`（TypeScript strict モード）がエラーなしで通過する
- `pnpm lint`（ESLint）がエラーなしで通過する
- `pnpm format`（Prettier）を適用済み

### 3. テスト

- ユーザーストーリーのハッピーパスをカバーする E2E テスト（Playwright）が存在する
- `pnpm test:e2e` が全テスト通過する

> E2E テストを省略する場合は PR 説明に理由を明記すること。理由なき省略は認めない。

### 4. セキュリティ・アクセス制御

実装内容に応じて以下を確認する。

| 確認項目                                                 | 確認方法                                                                                                         |
| -------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| RLS が正しく設定されている                               | 別の会員アカウントでログインし、他会員のデータ（注文・住所・カート等）にアクセスできないことをステージングで確認 |
| 未認証ユーザーは `/invite` と `/login` 以外に 404 が返る | 未ログイン状態で直接 URL アクセスして確認                                                                        |
| ランク制限商品は対象外ランクに表示されない               | 対象外ランクのアカウントで商品一覧・詳細 URL にアクセスして確認                                                  |
| Stripe Webhook エンドポイントが署名検証を実装している    | コードレビューで確認                                                                                             |
| 管理者・運営者機能が会員ロールからアクセスできない       | 会員アカウントで管理画面 URL に直接アクセスして確認                                                              |

### 5. PR レビュー

- PR が作成され、少なくとも1名がレビュー・承認済み
- PR 説明にストーリー ID（例: `BRAND-XX`）・変更内容・テスト手順が記載されている

### 6. CI が全グリーン

- GitHub Actions の全チェックが通過している

### 7. Linear チケットの更新

- 対応する Linear チケットのステータスが「Done」に更新されている

---

## バグ修正の完了基準

1. 再現手順が PR 説明に記載されている
2. 修正後に同じ手順で再現しないことをステージングで確認済み
3. 同種のバグを防ぐためのテストが追加されている（追加が困難な場合は理由を明記）
4. 上記「コード品質」「CI が全グリーン」「PR レビュー」を満たしている

---

## ステージング確認の原則

- **動くソフトウェアでの確認が最優先**。コードレビューのみで「完了」としない
- 運営者側の操作（注文ステータス更新・請求書発行等）は管理者アカウントで確認する
- 会員側の操作は複数のランク（少なくとも最低ランクと上位ランクの1つ）で確認する

---

## 完了の定義に含まれないもの

- 本番環境へのデプロイ（デプロイは別途リリース判断）
- パフォーマンス最適化（別途タスクとして扱う）
- `collaboration.md`・`definition-of-done.md` 等のドキュメント更新（コードに影響しない変更）
