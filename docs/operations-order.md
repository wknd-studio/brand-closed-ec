# 注文対応オペレーションマニュアル

このドキュメントは、注文ステータスごとに**運営者が実際に行う作業**を記述したものです。  
システムの設計意図（フロー・ステータス定義）は [order-flow.md](./order-flow.md) を参照してください。

---

## 担当ロール早見表

| ステータス             | 主担当         | 作業の種類               |
| ---------------------- | -------------- | ------------------------ |
| `confirming`           | 請求・顧客担当 | 価格確認・Invoice発行    |
| `invoice_sent`         | 請求・顧客担当 | 入金待ち・フォローアップ |
| `pending_payment`      | （対応不要）   | システムが自動処理       |
| `paid`                 | 調達担当       | 仕入れ先への手配開始     |
| `sourcing`             | 調達担当       | 発注確定                 |
| `ordered`              | 調達担当       | 入荷待ち・検品           |
| `preparing`            | 調達担当       | 梱包・発送               |
| `shipping`             | 調達担当       | 配達完了確認             |
| キャンセル（paid以前） | 請求・顧客担当 | Stripe Invoice void      |
| キャンセル（paid以降） | 管理者のみ     | Stripe 返金処理          |

---

## 1. `confirming`（注文確認中）— Invoiceフローのみ

> **担当:** 請求・顧客担当 / 管理者

### やること

1. **注文通知メールを受信する**  
   会員が注文を確定した時点でシステムから通知メールが届く（BRAND-64で実装予定）。

2. **管理画面で注文詳細を開く**  
   `管理画面 → 注文一覧 → 対象注文` を開き、要相談商品の内容（商品名・数量）を確認する。

3. **仕入れ先に在庫・価格を問い合わせる**  
   電話・メール・LINEなど既存の連絡手段で問い合わせる。  
   「○○を○個、いくらで入れられますか？」という形で確認する。

4. **請求単価を計算する**  
   `仕入れ価格 ÷ (1 - 利益率)` の計算を行い、会員への請求単価を決定する。

5. **Invoice発行フォームに単価を入力して発行する**  
   注文詳細画面下部の「Invoice発行」フォームに各要相談商品の単価を入力し、「Invoice発行」ボタンを押す。  
   Stripe Invoice が会員のメールアドレスに自動送付され、ステータスが `invoice_sent` に移行する。

### 注意点

- 支払い期限はデフォルト**7日間**。急ぎの場合は Stripe ダッシュボードで期限を短縮できる。
- 仕入れ先の回答待ちが長引く場合は、会員に「現在価格確認中です」と一報入れる。
- 月次仕入れ上限を超える場合、Invoice発行がシステムでブロックされる。その際は会員にプランアップグレードを案内する（[service-spec.md](./service-spec.md) のプラン詳細を参照）。

---

## 2. `invoice_sent`（請求書送付済み）— Invoiceフローのみ

> **担当:** 請求・顧客担当 / 管理者

### やること

1. **会員の支払いを待つ（最大7日間）**  
   Stripe Invoice の支払いが完了すると Webhook でシステムが自動的に `paid` に移行する。  
   この間、運営者は原則として何もしなくてよい。

2. **（任意）支払い状況を Stripe で確認する**  
   Stripe ダッシュボード → 「請求書」 → 対象 Invoice を開いて支払い状況を確認できる。

3. **期限が近い / 超過した場合**
   - 支払い期限の前日までを目安に、会員に「お支払いの確認」メールを送る（システム外で対応）。
   - 期限を延長する場合は Stripe ダッシュボードで Invoice を編集して期限を変更する。
   - キャンセルに決まった場合は「キャンセル手順」セクションを参照。

### 注意点

- 会員がStripe Invoiceのメールを受け取れていない場合がある。Stripeダッシュボードから Invoice の「再送」ができる。
- 「支払い済みなのにステータスが変わらない」という問い合わせが来た場合、Stripe ダッシュボードで `invoice.paid` Webhook の配信状況を確認する。

---

## 3. `pending_payment`（決済待ち）— Checkoutフローのみ

> **担当:** なし（システムが自動処理）

会員が Stripe Checkout ページで決済を完了すると Webhook で自動的に `paid` に移行する。  
運営者はこの画面で何もしなくてよい。

### ただし確認が必要なケース

- **Stripe Checkout Session の有効期限（24時間）が切れた場合**  
  Session が失効した注文は `pending_payment` のまま残り続ける。  
  フェーズ2でバッチ処理を実装予定だが、それまでは定期的に古い `pending_payment` 注文を確認し、手動でキャンセルする。  
  目安：注文日時から1日以上経過した `pending_payment` は失効済みとみなしてよい。

---

## 4. `paid`（入金確認済み）→ `sourcing`（手配中）

> **担当:** 調達担当 / 管理者

### やること

1. **入金確認通知を受け取る**  
   システムから運営者に入金確認メールが届く（BRAND-64で実装予定）。

2. **注文詳細で商品内容を確認する**  
   商品名・数量・会員情報を確認する。  
   要相談商品の場合、Invoice発行時に確定した単価も確認する。

3. **「手配を開始する →」ボタンを押す**  
   管理画面でステータスを `sourcing` に進める。

4. **仕入れ先に正式発注する**  
   電話・メール・発注システムなどで仕入れ先に発注する。  
   発注時に納期の確認も行う。

---

## 5. `sourcing`（手配中）→ `ordered`（発注完了）

> **担当:** 調達担当 / 管理者

### やること

1. **仕入れ先から発注確定・納期の連絡を受け取る**

2. **「発注完了にする →」ボタンを押す**  
   管理画面でステータスを `ordered` に進める。

### 注意点

- 仕入れ先から「在庫なし」の連絡が来た場合はキャンセル対応が必要になる。その場合は管理者に相談する。
- 納期が大幅に遅れる場合は会員に連絡する（システム外で対応）。

---

## 6. `ordered`（発注完了）→ `preparing`（発送準備中）

> **担当:** 調達担当 / 管理者

### やること

1. **仕入れ先から商品が届く**

2. **検品する**
   - 注文内容（商品名・数量）と合致しているか確認する
   - 破損・汚れがないか確認する
   - 問題がある場合は仕入れ先に連絡する

3. **「発送準備中にする →」ボタンを押す**  
   管理画面でステータスを `preparing` に進める。

---

## 7. `preparing`（発送準備中）→ `shipping`（配送中）

> **担当:** 調達担当 / 管理者

### やること

1. **商品を梱包する**
   - 緩衝材で商品を保護する
   - 必要に応じてギフト包装を行う（会員から要望があった場合）

2. **配送伝票を作成する**
   - 宅配業者のシステムまたは伝票に会員の住所・氏名を入力する
   - 追跡番号を取得する

3. **管理画面で追跡番号を入力し「発送済みにする →」ボタンを押す**  
   ステータスが `shipping` に移行し、会員に発送通知メールが送られる（BRAND-69で実装予定）。

4. **荷物を配送業者に引き渡す**  
   持ち込みまたは集荷依頼で配送業者に引き渡す。

### 注意点

- 追跡番号の保存は現在未実装（BRAND-69で対応予定）。  
  それまでの間は、追跡番号を別途スプレッドシート等で管理する。
- 発送通知メールも未実装のため、会員から「発送されましたか？」という問い合わせが来ることがある。現時点では手動で連絡する。

---

## 8. `shipping`（配送中）→ `delivered`（配送完了）

> **担当:** 調達担当 / 管理者

### やること

1. **配達完了を確認する**  
   以下のいずれかの方法で確認する：
   - 宅配業者の追跡サイトで配達完了ステータスを確認する
   - 会員から「届きました」という連絡を受け取る

2. **「配達完了にする →」ボタンを押す**  
   管理画面でステータスを `delivered` に進める。  
   会員に配送完了通知メールが送られる（BRAND-69で実装予定）。

### 注意点

- 不在で届かない場合は宅配業者が不在票を残す。会員が再配達の手配をする。
- 「届いていない」という問い合わせが来た場合は追跡番号で調査する（現在は別途管理中）。
- 配達完了の確認は、荷物を引き渡した翌日〜翌々日を目安に行う。

---

## 9. キャンセル対応

### 9-1. `pending_payment` でのキャンセル

> 管理者 / 請求・顧客担当

1. 管理画面でキャンセルボタンを押す
2. Stripe ダッシュボードでの追加作業は不要  
   （Stripe Checkout Session は自動で失効する）

---

### 9-2. `confirming` でのキャンセル

> 管理者 / 請求・顧客担当

1. 管理画面でキャンセルボタンを押す
2. Stripe での追加作業は不要（Invoice未発行のため）

---

### 9-3. `invoice_sent` でのキャンセル

> 管理者 / 請求・顧客担当

1. 管理画面でキャンセルボタンを押す
2. **Stripe ダッシュボードで Invoice を無効化（Void）する**  
   `Stripe ダッシュボード → 請求書 → 対象Invoice → 「請求書を無効にする」`  
   ※ Void しないと会員のメールに支払い催促が届き続ける

---

### 9-4. `paid` 以降のキャンセル

> **管理者のみ**（権限に注意）

1. 管理画面でキャンセルボタンを押す
2. **Stripe ダッシュボードで返金処理を行う**  
   `Stripe ダッシュボード → 支払い → 対象の支払い → 「返金」`
   - 全額返金か一部返金かを判断する
   - 返金理由を入力する（社内記録のため）
3. 会員に返金完了の旨を連絡する（システム外で対応）

> **注意:** `shipping`（配送中）以降のキャンセルは、配達を止めることが困難なため原則対応不可。会員から返品の申し出があった場合は管理者が個別に判断する。

## 10. よくあるトラブルと対応

| トラブル                                           | 確認場所                                   | 対応                                                                       |
| -------------------------------------------------- | ------------------------------------------ | -------------------------------------------------------------------------- |
| 支払い完了なのにステータスが `invoice_sent` のまま | Stripe ダッシュボード → Webhook → 配信ログ | Webhook の配信失敗を確認。再送または手動でステータス更新を管理者に依頼     |
| `pending_payment` が1日以上経過している            | 注文詳細の注文日時                         | Stripe Session が失効。管理画面からキャンセル処理を行う                    |
| 会員に Invoice メールが届いていない                | Stripe ダッシュボード → 請求書 → 「再送」  | Invoice を再送する                                                         |
| 仕入れ先から在庫なしの連絡が来た                   | —                                          | 管理者に報告。会員に謝罪の連絡をした上でキャンセル・返金処理を行う         |
| 会員から「追跡番号を教えて」と問い合わせが来た     | 発送時に記録した別途管理の追跡番号台帳     | 追跡番号を会員に連絡する（BRAND-69実装後はシステムから確認可能になる予定） |
