# Webhook

Stripe・ClerkのWebhook（`src/app/api/webhooks/`・`src/lib/webhook/`）の変更。外部から非同期に届くため、届き方を前提にしたバグは本番でしか起きないことが多い。

## 確認観点

- [ ] 署名の検証（検証より前にイベントの中身を使っていないか、検証に失敗したら処理せずに4xxを返すか）
- [ ] 再送への耐性（同じイベントが2回届いても、注文の確定・メール送信・在庫の更新が二重にならないか。冪等キーやイベントIDの記録）
- [ ] 順序の入れ替わり（後のイベントが先に届いたとき、状態が古いイベントで上書き・巻き戻りしないか）
- [ ] 応答コード（一時的な失敗では5xxで再送させ、再送しても直らない入力では2xxで打ち切っているか）
- [ ] 失敗の検知（catchで握りつぶさず `Sentry.captureException` で送っているか）
- [ ] 新しく扱うイベントの種類を、Stripe・Clerkのダッシュボードの送信設定にも足す必要があるか
