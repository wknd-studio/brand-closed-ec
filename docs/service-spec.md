# サービス仕様書

このドキュメントは「何をするサービスか・誰が使うか・どんなルールがあるか」を定義する。  
実装の詳細（データモデル・フロー・技術選定）は `data-model.md` / `order-flow.md` / `adr/` を参照。

---

## サービス概要

招待制クローズド EC。招待コードを持つ方のみ登録でき、特定ブランドの商品を卸売価格で仕入れられる。  
会員ランクごとに月額費用・月間仕入れ上限・商品単価・利用できる機能が異なる。

## 共通ルール（全会員）

- **招待コードは全ランクで必須**。招待なしでは登録できない。
- 全ランクで商品の閲覧・カートへの追加・購入が可能。
- 月間仕入れ上限はサブスク登録日を起点として1ヶ月ごとにリセット（例: 1/15登録 → 毎月15日リセット）。
- 商品にはランク制限を設定できる。最低閲覧ランクを下回る会員はその商品を閲覧・購入できない。
- **会員自身がいつでもランク変更可能**（セルフサービス）。変更は即時反映され、Stripe サブスクリプションが更新される。

## 招待システム

- 招待コードは **管理者** または **招待権限を持つ会員** が発行できる。
- 会員ごとに招待可否・招待上限数・使用済み招待数のステータスを持つ。
- 管理者は上記ステータスを自由に設定できる。
- 招待コードには有効期限・最大使用回数を設定できる。

## ランク変更ルール

### ランク変更フロー

```
会員がマイページでランク変更を選択
       ↓
新しいプラン内容・月額費用を確認
       ↓
変更を確定 → Stripe サブスクリプション変更 API を呼び出し
       ↓
Stripe Webhook で変更完了を受信
       ↓
会員のランクを新ランクに更新
```

### 変更後の月間仕入れ上限

ランク変更後もリセット日は変わらない（サブスク登録日起点を維持）。

**アップグレード時**

> ✅ 採用: 使用済み額を引き継ぐ
>
> 残り上限 = 新プランの上限 − 今月の使用済み額

**ダウングレード時**

> ✅ 採用: 警告表示 + 当月追加仕入れをゼロ
>
> - 既存の注文（注文確認中〜処理中）はそのまま継続（遡及キャンセルなし）
> - 残り上限 = max(0, 新プランの上限 − 今月の使用済み額)
> - ダウングレード確定前に「現在の使用額が新プランの上限を超えるため、当月はこれ以上仕入れできなくなります」旨の警告を表示

**要相談商品を含む注文のダウングレード後の請求書発行**

請求書発行時の月次上限チェックは「注文時点のプランの上限」を基準とする。注文レコードには発注時の月次上限額をスナップショットとして記録する。

## 退会・再入会

### 退会

- `delivered` / `cancelled` 以外の注文が1件でもある場合、退会をブロックする。
- 退会後もデータは保持する（論理削除）。
- 退会と同時に Stripe サブスクリプションを解約する。

### 再入会

> 🔲 TBD — クライアントとの確認が必要
>

> | 初期費用の再請求           | 再度請求する / 免除する / 一定期間経過後に再請求する |
> | 再入会時のランク           | 最初から選択 / 退会前のランクを引き継ぐ              |
> | 退会前データの引き継ぎ方針 | 注文履歴・住所を引き継ぐ / 新規扱いにする            |
