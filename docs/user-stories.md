# ユーザーストーリー

> ⚠️ **ランク名について**: 本ドキュメント中の「Free / Entry / Standard / Pro / Enterprise」という表記は旧5ランクモデル。既に実装済み・完了しているストーリー（AUTH-01/02/03/04/05等）は現行コードと一致しているためそのまま有効。一方、未実装のストーリー（PLAN-01/02等）は `service-spec.md` が定める新7ランクモデル（STARTER〜ENTERPRISE）・差分初期費用ロジックに沿って実装すること（コード移行は [BRAND-97](https://linear.app/wknd-studio/issue/BRAND-97) で管理）。ランク名・料金の正は常に `service-spec.md` を参照する。

## 記述ルール

### 形式

```
### US-XXX [タイトル]

**アクター**: [誰が]
**ストーリー**: [目的]のために、[操作]したい。

**受け入れ条件**:

【ユーザーが確認できること】
- ユーザー視点で観察できる振る舞い

【システムが保証すること】
- DB の更新・外部 API の呼び出し等、内部で起きること
```

### 記述例

```
### US-000 商品をカートに追加する（例）

**アクター**: 会員（全ランク）
**ストーリー**: まとめて注文内容を確認してから購入するために、商品をカートに追加したい。

**受け入れ条件**:

【ユーザーが確認できること】
- 「カートに追加」ボタンをクリックするとカートに商品が追加される
- 在庫が不足している場合はボタンが非活性になる
- 月間仕入れ上限を超える金額になる場合はエラーメッセージが表示される

【システムが保証すること】
- `inventory.reserved` がインクリメントされる（ソフト予約）
```

## 1. 登録・認証

### AUTH-01 会員登録

**アクター**: 未登録ユーザー
**ストーリー**: サービスを利用できるようにするために、招待コードを入力してメールアドレス・パスワードを登録し、プランを選択して入会したい。

**受け入れ条件**:

【ユーザーが確認できること】

- `/invite` ページに招待コード入力フォームが表示される
- 有効な招待コードを入力すると利用規約ページへ進む
- 無効・期限切れ・使用済みの招待コードはエラーメッセージが表示される
- 利用規約ページで規約全文を確認できる
- 「利用規約に同意する」チェックボックスにチェックを入れないと次へ進めない
- チェックを入れて「同意して登録へ進む」ボタンをクリックするとメールアドレス・パスワードの入力フォームへ進む
- メールアドレス・パスワードを入力して登録できる
- 登録後にプラン選択画面へ遷移し、Free / Entry / Standard / Pro から選択できる（Enterprise は管理者による個別設定が必要なため自己登録不可）
- 各プランの月額費用・月間仕入れ上限・機能が確認できる
- Free を選択すると商品一覧へリダイレクトされる
- 有料プランを選択すると AUTH-02（有料プラン登録時のサブスクリプション設定）のフローへ進む

【システムが保証すること】

- 利用規約に同意せずに Clerk の登録フォームへ遷移できない（同意前の URL 直打ちも防止する）
- 会員レコードが作成される（ランク: Free、オンボーディング未完了）
- 会員レコードに同意日時（`terms_agreed_at`）と同意時の規約バージョン（`terms_version`）が記録される
- Free を選択した場合はオンボーディング完了として記録される
- 使用した招待コードに使用者・使用回数が記録される

### AUTH-02 有料プラン登録時のサブスクリプション設定

**アクター**: 未登録ユーザー（有料プランを選択した場合）
**ストーリー**: 卸売価格で商品を仕入れられるようにするために、クレジットカードを登録して月額費用を支払いたい。

**受け入れ条件**:

【ユーザーが確認できること】

- Stripe のサブスクリプション登録フローへリダイレクトされる
- 月額費用と初期費用の内訳が確認できる
- クレジットカード情報を入力して支払いができる
- 決済成功後に商品一覧ページへリダイレクトされる
- 決済失敗時はエラーメッセージが表示され、プラン選択画面に戻る

【システムが保証すること】

- 決済完了後に会員のランクが選択プランに更新される
- オンボーディング完了として記録される

## 2. 商品閲覧

### PROD-01 商品一覧の閲覧

**アクター**: 会員（全ランク）
**ストーリー**: 仕入れたい商品を探すために、購入可能な商品の一覧を閲覧したい。

**受け入れ条件**:

【ユーザーが確認できること】

- 商品カード（商品名・サムネイル・参考小売価格・自分のランクの価格・在庫状況）が一覧表示される
- 自分のランクでは閲覧できないランク制限商品は一覧に表示されない
- 初期表示は新着順（登録日時の降順）
- スクロールが末尾に近づくと自動で次のページを読み込む（無限スクロール、1回あたりの件数: TBD）
- データ読み込み中はスケルトンが表示される
- すべての商品を読み込んだ場合は「すべての商品を表示しました」と表示される
- カテゴリ絞り込み・並び替え・キーワード検索は組み合わせて使用できる

【システムが保証すること】

- 自分のランクで閲覧可能な商品のみが返される

### PROD-02 商品のカテゴリ絞り込み

**アクター**: 会員（全ランク）

### PROD-03 商品詳細の閲覧

**アクター**: 会員（全ランク）
**ストーリー**: 仕入れの判断をするために、商品の詳細情報を確認したい。

**受け入れ条件**:

【ユーザーが確認できること】

## 4. 注文・決済

### ORDER-01 注文の確定

**アクター**: 会員（全ランク）
**ストーリー**: カートの内容を確定して仕入れを依頼するために、注文を送信したい。

**受け入れ条件**:

【ユーザーが確認できること】

- カート画面の「注文する」ボタンをクリックすると注文確認画面へ遷移する
- 注文確認画面ではお届け先住所・請求先住所が表示され、デフォルトに設定した住所が初期選択された状態になる
- 住所を変更・新規登録できる（住所未登録の場合はその場で新規登録できる）
- 固定価格商品の合計が月次仕入れ上限を超える場合は注文できずエラーメッセージが表示される
- 要相談商品はカートに追加・注文できるが、価格は「要相談」として表示され合計金額には含まれない
- 内容を確認して「注文を確定する」ボタンをクリックすると、カートの内容に応じて以下のいずれかのフローに自動で進む:
  - **全商品が固定価格の場合（Checkout フロー）**: Stripe Checkout ページへリダイレクトされ、カード情報を入力して即時決済できる。決済完了後に注文完了画面が表示される
  - **要相談商品を1つでも含む場合（Invoice フロー）**: 注文番号・注文内容が表示され「請求書の送付をお待ちください」旨のメッセージが表示される

【システムが保証すること】

- **Checkout フロー**: 月次仕入れ上限チェック（全額）後に Stripe Checkout Session を作成し、注文が「決済待ち」として記録される。Stripe `checkout.session.completed` Webhook 受信後に「入金確認済み」へ自動更新される
- **Invoice フロー**: 月次仕入れ上限チェック（固定価格分のみ）後に注文が「注文確認中」として記録される。運営者に注文通知メールが送信される
- 注文内容（商品・数量・固定価格商品の単価・選択したお届け先住所・請求先住所・注文時点のランク・月次上限額）が記録される
- 注文確定後にカートが空になる
- 会員に注文完了メールが送信される（Checkout フロー: 決済確認後、Invoice フロー: 注文受付完了）

---

### ORDER-02 請求書の受け取りと支払い（Invoice フロー）

> **Invoice フロー専用**（要相談商品を含む注文のみ。全商品が固定価格の場合は ORDER-01 の Checkout フローで即時決済される）

- 請求顧客担当は「注文確認中」「請求書送付済み」の注文のみキャンセルできる（それ以降のステータスはキャンセルボタンが非表示）
- キャンセル前に確認ダイアログが表示される
- 「入金確認済み」以降のキャンセルは返金対応が必要な旨の警告が表示される（返金処理はシステム外で対応）
- キャンセル後に注文ステータスが「キャンセル」に更新される

【システムが保証すること】

- 注文が「キャンセル」として記録される
- 会員にキャンセル通知メールが送信される

### ADMIN-12 担当者アカウントの管理

**アクター**: 管理者
**ストーリー**: 運営チームを管理するために、担当者アカウントの追加・ロール設定・無効化をしたい。

**受け入れ条件**:

【ユーザーが確認できること】

- 管理画面から担当者を招待（メールアドレス入力）し、ロール（管理者 / 請求顧客担当 / 調達担当）を指定できる
- 既存の担当者のロールを変更できる
- 担当者アカウントを無効化でき、無効化後はその担当者がログインできなくなる
- 担当者一覧（名前・メール・ロール・状態）が確認できる

【システムが保証すること】

- 担当者の管理は Clerk の Organization / Role 機能で処理される
- 無効化された担当者は即時にアクセスできなくなる

### ADMIN-13 Enterprise 会員のサブスクリプション設定

**アクター**: 管理者
**ストーリー**: 個別契約の Enterprise 会員が月額費用を支払えるようにするために、Stripe でカスタムサブスクリプションを作成して会員に送付したい。

- 送付後、会員が Stripe のリンクからサブスクリプションを開始できる

【システムが保証すること】

- Stripe Webhook で支払い完了を受信後、会員のランクが Enterprise に更新される

### ADMIN-14 商品の一括インポート（Google スプレッドシート → Sanity）

> **CLI スクリプト運用**（初期段階）。運営者がスプレッドシートに商品情報を記入し、エンジニアがスクリプトを実行して Sanity へ一括登録する。将来的に Sanity Studio プラグイン化を検討する（フェーズ3以降）。

**アクター**: エンジニア（スクリプト実行者）／管理者・調達担当（スプレッドシート記入者）
**ストーリー**: 大量の商品を効率的に Sanity へ登録するために、Google スプレッドシートで作成した商品データを CLI スクリプトで一括インポートしたい。

**受け入れ条件**:

【エンジニアが確認できること】

- `npx tsx scripts/import-products.ts --sheet=<SheetID> --dataset=<production|staging>` で実行できる
- `--dataset` フラグが必須で、省略するとエラーになる（本番データへの誤実行防止）
- 実行前にバリデーション結果（対象件数・エラー行の一覧）がプレビュー表示され、確認後に続行できる
- インポート完了後に登録件数・スキップ件数（エラー行）がターミナルに出力される

【システムが保証すること】

- スプレッドシートは所定のフォーマット（`docs/spreadsheet-template.md` で定義）に従って解析される
- 必須項目（商品名・ランク別価格）が欠けている行はスキップされ、エラーとして報告される
- インポートされた商品は Sanity API 経由で Sanity に登録される（画像はスキップ。Sanity Studio で別途追加）
- インポート処理は行単位でコミットされ、途中のエラーが後続行の処理を止めない
