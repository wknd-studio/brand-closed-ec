# Quickstart: 7ランクモデル移行の動作確認

## 前提

- `supabase start` でローカルDBが起動していること
- Stripeテストモードで7ランク分のPrice IDが作成済みであること
- Sanity Studioの`product`スキーマが7ランクに更新済みであること

## 検証シナリオ

### シナリオ1: 新規会員登録

1. 招待コードで新規登録を開始する
2. プラン選択画面で6ランク（STARTER〜PREMIUM）が表示されることを確認する
3. STARTERを選択して登録を完了する
4. **期待結果**: `users.rank = 'starter'`。Stripeでstarterの価格でサブスクリプションが作成される

### シナリオ2: カタログのアクセス制御

1. STARTERランクの会員でログインする
2. STANDARD限定商品のページに直接アクセスする
3. **期待結果**: 閲覧できない旨が表示される
4. PREMIUMランクの会員でログインし、同じ商品ページにアクセスする
5. **期待結果**: 商品が正しく表示される

### シナリオ3: 月次仕入れ上限チェック

1. 任意のランクの会員で、そのランクの月間仕入れ上限に近い金額をカートに入れる
2. 上限を超える注文を確定しようとする
3. **期待結果**: 上限超過が新ランクの上限値で正しく判定される

### シナリオ4: 注文確定後のランクスナップショット

1. 会員が注文を確定する
2. 管理画面で該当注文の`rank_at_order`を確認する
3. **期待結果**: 確定時点のランク（7ランクの値）が記録されている

## 実行コマンド

```bash
supabase start
supabase db reset
pnpm test
pnpm test:e2e   # サインアップ〜カタログ〜注文確定のE2E
```
